# MiniMax 列传

## 史家总评

MiniMax 的路线不是单押文本聊天，而是从一开始就把文本、语音、图像、视频、音乐和角色化交互放进同一家公司。它试图建立的是“全模态模型公司”，并通过海螺、星野、开放平台和企业 API 把模型能力分发出去。

## 一、家世与初战

MiniMax 的团队来自自然语言处理、推荐、语音和互联网产品背景。其产品早期重视角色对话、情感陪伴和内容生成，随后逐步扩展到文本基座、语音合成、视频生成、音乐和多模态模型。

2023 年，MiniMax 的语音大模型开始服务企业场景；这条路线后来成为其区别于纯文本创业公司的重要资产。声音不是文字的附属，而是实时交互、数字人、教育、玩具和内容生产的入口。

## 二、成长与变法

### 1. 从陪伴产品到模型平台

海螺等产品把文本模型和语音交互结合起来，强调自然、多情感和长期陪伴。MiniMax 同时建设开放平台，为开发者提供文本、语音和多模态 API。

### 2. 多模态模型家族

2024 年，MiniMax 持续发布和升级文本、语音、视频、音乐等模型，并在伙伴生态中展示大规模交互与内容生成场景。模型的竞争单位由“回答质量”扩展到语音延迟、视频时序、音乐表现和跨模态一致性。

### 3. MiniMax-01：长上下文与新架构

2025 年 1 月，MiniMax 发布并开源 MiniMax-01 系列，包含 Text-01 与 VL-01，并尝试以线性注意力与混合架构降低超长上下文的计算成本。这是其从产品驱动走向基础架构创新的重要一步。

## 三、2025 年：推理模型与 Agent 化

MiniMax-01 之后，MiniMax 在 2025 年继续把长上下文、多模态、推理、代码和 Agent 工作流并入模型平台。其路线一端强调开放模型与开发者调用，另一端强调陪伴、创作和面向普通用户的产品体验。

## 四、功与边界

MiniMax 的全模态路线能覆盖更多消费和创作场景，但每种模态都有独立的质量、安全、版权和成本问题。语音克隆涉及身份与同意，视频和音乐涉及版权与肖像，角色产品还涉及未成年人保护和情感依赖。

## 五、2026 年：M2.5、M3 与全模态平台

2026 年，MiniMax 连续推进 M2.5、M3、Music-3.0 与 H3，把编程、工具调用、1M 上下文、文本/图像/视频/音频和音乐放入同一产品谱系。MiniMax 的历史位置由“陪伴产品公司”进一步转向“全模态模型与 Agent 平台”。

|---|---|
| 2023 | 语音大模型进入企业服务场景 |

| 2024-09 | 发布伙伴生态与新一代多模态技术路线 |
| 2025-01-15 | MiniMax-01 开源，强调超长上下文与线性注意力 |
| 2025 | 推理、编码和 Agent 能力继续扩展；模型创新与产品平台并行推进。 |

> **史家曰**：MiniMax 不满足于让机器会说话，而要让机器会听、会看、会唱、会演。全模态是一条宽路，亦是一条难路；每多一种感官，便多一层真实世界的责任。
