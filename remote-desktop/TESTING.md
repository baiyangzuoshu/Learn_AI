# 双机验收步骤

当前状态：macOS ARM64 应用和 Windows x64 安装包已构建；真实 macOS ↔ Windows
互控尚未验收。

## 准备

- 两台电脑处于同一局域网。第一轮不使用公网、VPN 或混合 DPI 多屏。
- macOS 安装 `releases/mac-arm64/LinkDesk.app`，Windows 安装
  `releases/LinkDesk Setup 0.1.0.exe`。
- macOS 允许 LinkDesk 的屏幕录制和辅助功能。授权后重启应用。
- Windows 使用普通桌面和普通权限应用，避开 UAC
  对话框、锁屏和管理员窗口。脚本被组织策略阻止时，记录错误；不要为了测试绕过组织策略。

## 启动信令服务

在本机仓库终端执行下面命令，将示例 IP 替换为 Mac 的局域网 IP：

```sh
cd /Users/youjunmao/WORK/Learn_AI/remote-desktop
LINKDESK_HOST=192.168.1.10 npm run relay
```

本次已经生成 `.local/cert.pem` 和 `.local/key.pem`，无需重复运行
`certificate`。服务启动后会显示公开的证书 SHA-256 指纹；私钥不复制到客户端。

两台应用输入相同的 `https://192.168.1.10:9443`
和相同的证书指纹，然后点击“上线”。需要在信令主机的防火墙允许端口
9443。服务没有设备列表公开接口，也不会自动配置端口映射。

## 正向测试：Mac 控制 Windows

1. 从 Windows 应用读取其设备编号和临时密码，输入 Mac 应用并连接。
2. Windows 应用应显示 Mac 的名称和设备编号。先拒绝一次，确认 Mac
   收到拒绝提示且没有远程画面。
3. 再次连接，Windows 选择主屏并勾选允许键鼠控制。确认后，Mac 应显示 Windows
   的实时画面。
4. 在 Windows 打开记事本。Mac 点击远程记事本窗口，输入 `abc123`，测试
   Shift、Backspace、Enter、方向键及 Ctrl+A。
5. 测试点击、拖动窗口、滚轮以及画面缩放。视频黑边不应改变有效画面内的鼠标坐标。
6. 在 Windows 点击断开。Mac
   应停止画面与控制；先前按住的键和鼠标按钮不应继续保持按下。

## 反向测试：Windows 控制 Mac

1. 使用 Mac 的编号和临时密码，从 Windows 连接。
2. Mac 选择屏幕并允许连接。Windows 应显示实时画面。
3. 在 Mac 的文本编辑应用中重复基础键鼠测试。这里发送物理键位，不自动把 Windows
   Ctrl 映射为 macOS Command；需要 Command 时使用对应的 Meta/Windows 键。
4. 分别验证被控端的断开按钮和 `Cmd/Ctrl + Shift + Esc` 全局快捷键。

## 边界测试

| 场景                 | 预期                                     |
| -------------------- | ---------------------------------------- |
| 输入错误密码         | 拒绝连接，不出现远程画面                 |
| 被控端选择仅查看     | 画面可见，远程键鼠无效                   |
| 未授权辅助功能       | 控制启动失败，提示授权；不能默默注入输入 |
| 任一端关闭应用       | 停止共享与键鼠子进程，另一端结束会话     |
| 控制端切换到其他窗口 | 释放已按住的远程按键                     |
| 断网                 | 连接中断后停止共享和输入；需要重新连接   |
| 设备下线再上线       | 新编号、新临时密码，旧凭证失效           |
| 更换为错误证书指纹   | TLS 连接失败，不发送设备凭证             |

确认局域网两种方向通过后，再使用自己的 STUN/TURN 服务测试跨网络连接。没有 TURN
时，跨 NAT 连接失败不能证明视频或输入功能有问题。

记录故障时提供：控制方向、操作系统版本、最后一个成功步骤和界面错误文字。不要提供临时密码、设备凭证、证书私钥或
TURN 凭证。
