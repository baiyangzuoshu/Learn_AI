> “模型可以请求动作，不能批准自己的权限”
>
> Harness 层：权限。本章只增加一个机制，Agent 的核心决策循环保持不变。

## 本章目标

学完后，你应该能解释这个机制解决的具体问题、指出它插入 Agent Loop
的位置，并能修改一个约束后验证行为变化。

## 问题

同一个工具既可能只读，也可能破坏数据；仅按工具名允许或拒绝无法表达真实风险。

## 解决方案

把完整 ToolRequest 交给授权器，区分 ask、auto、full，并保留不可绕过的危险动作后盾。

## 工作原理

1. 识别请求的副作用与目标。
2. 先执行 hard-deny 安全检查。
3. 再按 permission mode 决策。
4. 把拒绝原因作为工具结果返回。

### 执行链

```text
tool request → hard deny → mode policy → approval → execute/deny
```

模型负责决定下一步，Harness 负责校验、执行、记录和限制。失败也作为观察返回模型，而不是被隐藏。

## 边界与生产差距

教学正则不是沙箱；生产权限必须结合规范化路径、工具元数据、外部目标、审计和用户显式选择。

课程代码为了突出机制会使用简化存储、协议或策略。不要把它直接导入 `src/`；迁移时应围绕生产
Registry、Runtime 和 Feature 契约重新实现。
