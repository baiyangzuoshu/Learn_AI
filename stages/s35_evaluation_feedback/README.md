> “任何一项缺证据，都不能称为迁移完成”
>
> 生产层：验收。本章把前二十课的教学机制收紧为可执行、可观察、可验收的约束。

## 本章目标

学完后，你应该能说明该能力为什么属于生产
Harness、它依赖哪些证据，以及缺少哪项检查时必须阻断迁移或发布。

## 问题

教学示例“有实现”不代表它满足生产契约、集成、安全、回滚或目标平台运行要求。

## 解决方案

为每项能力建立 Acceptance Matrix，只有全部检查携带真实证据时才允许迁入生产。

## 工作原理

1. 列出公开契约与目标模块。
2. 关联自动化和集成测试。
3. 附加 Trace、安全与回滚证据。
4. 缺项时返回明确 missing 列表。

### 执行链

```text
course behavior → feature design → evidence matrix → accept / block
```

这里的类和函数是可运行的最小模型，用来暴露状态机与边界；它们不是生产服务的替代品。

## 观察清单

通过 fail 参数让每个矩阵项轮流失败，确认没有任何能力被默认豁免。

观察时要区分“示例返回了正确
JSON”和“生产系统具备持久化、并发、安全、取消与运营证据”这两个完全不同的结论。

## 边界与生产差距

示例中的 verified 是占位文本；真实验收必须链接测试产物、负责人、回滚方案、文档和原生平台验证。

生产迁移必须通过 `AgentRuntime`、`ToolRegistry`、`PromptRegistry` 和独立 `HarnessFeature`
完成；禁止从 `src/` 或 `desktop/` 直接导入课程代码。

## 动手练习

1. 修改一个阈值或状态转移，写下预期结果并运行本章验证。
2. 增加一个负例，确认失败会留下可定位证据，而不是被吞掉或误报成功。
3. 把本章机制映射到生产模块，列出契约、持久化、权限、Trace、取消和回滚要求。

## 过关标准

- 能画出执行链并解释每个边界由谁强制。
- 能指出示例中的占位实现和至少三项生产缺口。
- 能给出一条可自动化的验收证据，而不是“人工看起来没问题”。
