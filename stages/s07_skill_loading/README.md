## 本章目标

学完后，你应该能解释这个机制解决的具体问题、指出它插入 Agent Loop
的位置，并能修改一个约束后验证行为变化。

## 问题

启动时注入所有技能会持续占用上下文，还会让无关流程互相干扰。

## 解决方案

把 Skill 与 Tool 分离：list_skills 只展示目录，load_skill 才读取一个受信范围内的 SKILL.md。

## 工作原理

1. 扫描受限技能根目录。
2. 校验安全名称并处理优先级。
3. 返回轻量目录。
4. 只加载当前任务相关的完整说明。

### 执行链

```text
discover → select → load one skill → use existing tools
```

模型负责决定下一步，Harness 负责校验、执行、记录和限制。失败也作为观察返回模型，而不是被隐藏。

## 观察清单

创建一个测试 Skill，确认非法名称、缺失文件和无关技能都不会被预加载。

建议同时记录：模型看见了什么 Schema、Harness
实际执行了什么、结果如何回到消息历史，以及取消或失败发生在哪一层。

## 边界与生产差距

生产实现还需处理来源信任、同名优先级、符号链接、版本、依赖和正文预算。

课程代码为了突出机制会使用简化存储、协议或策略。不要把它直接导入 `src/`；迁移时应围绕生产
Registry、Runtime 和 Feature 契约重新实现。
