# s08：上下文压缩

源码：[s08_context_compact.ts](../s08_context_compact.ts)

## 学习目标

- 理解上下文窗口为什么需要预算。
- 掌握保留近期消息、压缩早期历史的基本策略。
- 认识字符预算与 Token 预算的差异。

## 核心机制

历史超过阈值后，早期消息被压缩成摘要，近期对话原样保留，并发出 `ContextCompact`
Hook。压缩必须保留目标、关键决策、未完成工作和验证证据。

## 压缩的是成本，不是目标

上下文窗口既是硬限制，也是注意力预算。永久保留每次长输出、失败尝试和旧讨论，会让当前目标被噪声淹没。压缩不是简单删字，而是用更低成本保留未来决策仍需要的信息。

`compactHistory()` 超预算后把历史分成 `older` 与最近 10 条
`recent`。旧消息被规范空白、逐条截断并合成受限摘要，近期消息保持原文。近期工具参数、错误文本和用户修正往往需要精确内容；摘要应保留目标、约束、决策、修改、未完成项和验证证据。

当前是确定性字符压缩，不真正理解内容。生产方案通常先截断工具输出，再移除可重建观察，再做结构化摘要，最后才调用模型总结。`ContextCompact`
Hook 让上下文改变可追踪，否则信息丢失会表现为难以解释的行为漂移。

## 运行与观察

```sh
deno task s08
```

构造较长历史，观察压缩前后长度，以及最近消息是否仍保持原文。
