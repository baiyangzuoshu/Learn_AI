# s16：团队通信协议

源码：[s16_team_protocol.ts](../s16_team_protocol.ts)

## 学习目标

- 理解团队成员之间的定向与广播消息。
- 掌握异步上下文中的团队身份。
- 认识内存消息板的生命周期限制。

## 核心机制

`team_send` 写入包含发送者、接收者、类型、内容和时间的消息；`team_inbox`
只返回与当前成员相关的信息；`team_protocol_run` 将通信能力加入团队执行。

## 协作需要机器可验证的语言

成员只返回最终文本时，无法在执行中共享发现、请求帮助或确认依赖。协议消息把通信变成结构化信封：谁发送、发给谁、消息类型、内容和时间都可校验、路由与审计。

`team_send`
从异步上下文读取真实发送者，而不是信任模型填写身份；接收方可以是具体成员或广播目标。`team_inbox`
只返回当前成员有权看到的消息。`team_protocol_run` 在团队执行期间注入身份和通信工具，使同一个工具
Handler 能按调用者隔离数据。

内存消息板适合展示协议，但应用重启会丢失数据，也没有消费确认。可靠邮箱需要消息
ID、持久化、未读游标、幂等去重、确认/拒绝、过期和背压。不要在广播中携带秘密或无限长上下文。

协议的目标不是增加“聊天感”，而是让依赖、请求、结果和失败能够驱动下一步动作。

## 运行与观察

```sh
deno task s16
```

要求成员广播关键发现并在结束前读取 inbox，检查消息可见范围。

## 练习

增加
`messageId`、ACK、去重和未读游标，并持久化邮箱。模拟成员读取后进程崩溃，明确恢复时消息应重投还是视为已消费。
