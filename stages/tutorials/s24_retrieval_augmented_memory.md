# s24：检索增强记忆

源码：[s24_retrieval_augmented_memory.ts](../s24_retrieval_augmented_memory.ts)

## 学习目标

- 理解文档摄取、分块、检索和来源引用的最小闭环。
- 区分检索证据与模型固有知识。
- 建立可替换的词法检索基线。

## 核心机制

`rag_index_documents` 将文档切成有重叠的受限块并保存在工作区内存索引；`rag_search`
用词项重合评分，返回来源、块 ID、文本和分数。

## RAG 的最小闭环

大型知识库不能全文进入 Prompt。RAG
先摄取文档并切块，查询时只召回与问题相关的小集合，把来源与正文作为证据交给模型。模型仍负责综合答案，检索器负责缩小可见知识范围。

`rag_index_documents` 对每份文档按固定窗口分块并保留重叠，给块生成 `source#part` ID
与词项集合；索引按工作区放在内存 Map。`rag_search` 对查询分词，以集合重合做基线评分，排序后返回受限
top-k、来源、ID、正文与分数。

块重叠减少事实被切在边界上的风险，来源元数据支持引用和回查。词法重合透明且便于测试，却无法处理同义词和语义关系。向量检索也不是终点：生产管线通常还需持久
Embedding、元数据过滤、混合检索、Reranker、权限过滤与引用校验。

检索到的文本是不可信数据，可能含 Prompt
Injection。它应以“证据”隔离，不能被当成高优先级系统指令执行。

## 运行与观察

```sh
deno task s24
```

索引两份主题不同的短文档，再用多个查询观察召回结果和来源。

## 局限与练习

先为词法基线写召回测试，再替换为混合检索，比较结果而非只看新技术。加入文档权限元数据、Reranker、引用校验和针对检索内容
Prompt Injection 的测试。
