# s15：Agent Teams

源码：[s15_agent_teams.ts](../s15_agent_teams.ts)

## 学习目标

- 将大任务拆成多个不重叠的专家任务。
- 掌握 2–4 个成员的并行执行与结果汇总。
- 理解部分失败为什么不能丢弃其他成员结果。

## 核心机制

`team_run` 使用 `Promise.allSettled`
并行运行成员。每名成员获得角色、子任务和共同目标，最终结果保留成功与失败状态。嵌套团队被禁止。

## 团队不是无限复制模型

团队适合可独立并行、视角不同且最终能合并的任务。每个成员得到共同目标、自己的角色与不重叠子任务；协调者负责定义边界和汇总，而不是让所有成员重复完成同一件事。

`team_run` 限制 2–4 名成员，并用 `Promise.allSettled` 并行执行。选择 `allSettled` 而不是
`Promise.all` 很重要：一名成员失败时，其他成功证据仍有价值。最终返回每个成员的状态，使主 Agent
能决定重试、降级或基于部分结果继续。

`teamActive`
阻止团队嵌套，防止指数级派生。生产实现还应共享总预算而不是给每名成员无限额度，传播取消，限制工具权限，控制输出，并对修改同一文件的任务做冲突分析。

适合的拆分如“安全审查 / API 设计 / 测试分析”；不适合把高度串行的同一函数修改硬拆给多人。

## 运行与观察

```sh
deno task s15
```

让两个专家分别分析安全和架构，观察并行结果以及一个成员失败时的汇总行为。

## 练习

增加团队共享工具调用与 Token
预算，而非每人独立满额。让一名成员失败，验证其他结果仍返回；再设计两个会修改同一文件的子任务并在启动前拒绝冲突。
