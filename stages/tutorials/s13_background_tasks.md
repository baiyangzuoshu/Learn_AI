# s13：后台任务

源码：[s13_background_tasks.ts](../s13_background_tasks.ts)

## 学习目标

- 理解长时间命令为何不应阻塞 Agent Loop。
- 掌握后台进程的启动、查询、取消和输出限制。
- 处理并发上限和进程生命周期。

## 核心机制

`background_start` 启动子进程并立即返回任务 ID，`background_status` 查询状态，`background_cancel`
发送终止信号。任务记录包含工作区，避免跨项目读取。

## 后台化改变控制流

构建、测试和开发服务器可能运行数秒甚至永不退出。同步等待会让 Agent
无法继续读取文件、分析其他问题或响应取消。`background_start` 只负责启动并返回 ID，后续通过
`background_status` 获取受限增量观察，通过 `background_cancel` 结束进程。

源码维护任务
Map，记录命令、工作区、状态、输出和进程句柄。工作区绑定防止一个项目读取另一个项目的任务；并发上限避免模型无限生成进程；输出截断避免日志吞噬内存。进程结束时必须更新状态并产生可被
Agent 看见的完成通知，否则模型只能低效轮询。

真正困难的是生命周期：父运行取消时，子进程不能变成孤儿；应用退出时应终止或明确分离；先发送温和信号，超时后再强制终止；Shell
创建的进程树也要整体处理。状态查询还应使用游标，避免每次返回全部日志。

后台任务是执行机制，不等于调度。s14 解决“未来何时启动”，本课解决“启动后不要阻塞”。

## 运行与观察

```sh
deno task s13
```

启动一个短暂的延迟命令，连续查询状态，再测试取消仍在运行的任务。

## 练习

传播父级
`AbortSignal`，增加温和终止后的强制清理，并让状态查询接受输出游标。启动会派生子进程的命令，验证整个进程树都被清理。
