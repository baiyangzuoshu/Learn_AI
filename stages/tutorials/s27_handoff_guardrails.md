# s27：Handoff 护栏

源码：[s27_handoff_guardrails.ts](../s27_handoff_guardrails.ts)

## 学习目标

- 用结构化信封表达 Agent 交接。
- 在交接时保留目标、证据、工具权限和预算。
- 拒绝含糊、自我交接和无证据交接。

## 核心机制

`handoff_validate` 校验发送者、接收者、目标、证据、工具白名单和工具预算，成功后生成唯一 Handoff
ID。它是流转前护栏，不负责执行目标 Agent。

## 交接不是复制整段聊天

可靠 Handoff
应传递接收者完成任务所需的最小充分状态：明确目标、已验证证据、允许工具、资源预算和期望输出。复制全部历史会把噪声和敏感信息一起扩散；只说“继续处理”又缺少可执行上下文。

`handoff_validate` 校验成员 ID、禁止自我交接、限制目标长度，要求 1–50
条证据，去重工具白名单，并把工具调用预算限定为 1–100。成功生成唯一 `handoffId`，为后续确认、Trace
和责任链提供关联键。

Validator
只证明信封结构有效，不代表证据真实，也不负责启动接收方。执行前还要根据接收方身份重新做权限交集：发送者不能借
Handoff 授予自己没有的能力。完成后输出也应满足约定 Schema，并附可复核证据。

生产协议需要接收确认、拒绝理由、超时回退、取消和审计；敏感证据应引用受控资源而非直接复制正文。

## 运行与观察

```sh
deno task s27
```

比较完整交接、无证据交接和发送者等于接收者三种输入。

## 局限与练习

增加接收方输出
Schema、ACK/拒绝、超时回退与权限交集检查。构造发送者试图扩大工具权限的信封，确认校验失败并进入审计轨迹。
