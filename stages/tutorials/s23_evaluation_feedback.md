# s23：评估与反馈

源码：[s23_evaluation_feedback.ts](../s23_evaluation_feedback.ts)

## 学习目标

- 在执行前定义可测量成功标准。
- 使用确定性 Grader 评估回答。
- 将失败证据用于下一轮改进。

## 核心机制

`evaluation_score` 支持 `contains`、`not_contains` 和 `exact`
三种规则，并按权重计算得分。确定性规则便于回归测试，也避免完全依赖模型自评。

## 从“看起来不错”到可回归

Agent 改动可能提高某类任务，却悄悄破坏权限、工具选择或回答格式。Eval
把成功标准变成可重复执行的样例与 Grader，使 Prompt、模型或 Harness 变更能比较，而不是靠主观试玩。

`Criterion` 支持包含、不包含与精确匹配，并给每项权重。`evaluateText()` 先生成逐项证据，再计算
earned/possible 与整体通过。确定性 Grader
便宜、稳定、容易定位失败，适合格式、安全禁词和关键事实；它无法判断开放式质量，必要时才加入人工评分或
LLM Judge。

完整 Eval
不应只检查最终文本，还可断言工具轨迹、权限请求、文件结果、延迟、成本和是否留下后台进程。数据集应包含正常、边界和对抗样例，并固定版本，避免只针对当前实现写“必过测试”。

评测结果形成反馈回路：发现失败 → 保存证据 → 修改一个变量 → 重跑同一数据集 → 比较回归，而不是把 Eval
分数直接塞给 Agent 自我优化。

## 运行与观察

```sh
deno task s23
```

对同一回答设置正向和负向规则，观察单项结果、总分和整体通过状态。

## 局限与练习

建立至少五条版本化 Dataset，加入工具轨迹、权限拒绝、延迟和成本断言。只对确定性规则无法覆盖的维度使用
LLM Judge，并保存其评分理由供人工抽查。
