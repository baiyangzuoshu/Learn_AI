# s09：项目长期记忆

源码：[s09_memory.ts](../s09_memory.ts)

## 学习目标

- 区分对话历史和跨会话项目记忆。
- 掌握按工作区隔离的读取、追加和替换。
- 理解记忆中不能保存密钥和短期噪声。

## 核心机制

`memory_read` 加载项目记忆，`memory_append` 追加稳定事实，`memory_replace`
用精简版本整体替换。记忆以工作区摘要作为文件标识，并通过事件显示加载或更新状态。

## 三种状态不要混用

- 对话历史回答“这次会话发生了什么”。
- Todo 回答“当前任务做到哪一步”。
- Memory 回答“下次进入项目仍应知道什么”。

稳定架构约束、用户长期偏好、验证过的命令适合记忆；密钥、临时错误、猜测、一次性进度和可随时从源码读取的事实不适合。

`memoryPath()` 对工作区计算 SHA-256 摘要，实现项目隔离。`readMemory()`
处理首次不存在并限制长度；`writeMemory()`
规范化正文、创建目录和控制预算。追加容易积累重复与冲突，因此 `memory_replace` 承担整理角色。

真实产品还应保存来源、时间、置信度与作用域，在写前扫描秘密，并使用原子写入。本阶段硬编码 macOS
数据目录只是教学简化，生产必须使用 `src/config/paths.ts`。当记忆变大后，也不应每轮全文注入，而应采用
s24 的检索方式。

## 运行与观察

```sh
deno task s09
```

保存一条稳定架构约束，重新运行后读取它；不要保存 API Key 或一次性任务状态。

## 练习

保存两条互相冲突的项目命令，设计来源和时间字段帮助判断；再加入去重、过期、秘密检测、冲突提示与原子写入。
