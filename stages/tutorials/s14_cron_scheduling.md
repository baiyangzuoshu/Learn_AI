# s14：周期 AI 对话

源码：[s14_cron_scheduling.ts](../s14_cron_scheduling.ts)

## 学习目标

- 理解定时任务如何复用同一个 Agent Loop。
- 掌握周期配置、持久化、超时和运行结果保存。
- 认识重复执行与单实例锁问题。

## 核心机制

`cron_list`、`cron_write` 和 `cron_run_now`
管理周期任务。调度器计算下次时间，到期后使用绑定工作区、模型和权限运行 Agent，并将回答保存为会话。

## 调度器不是第二个 Agent

调度器只负责保存“何时、在哪个工作区、用哪个模型和权限运行什么 Prompt”，到期后仍调用同一个 Agent
Loop。它不复制推理逻辑，也不把任务写成硬编码工作流。

`cron_write` 校验并持久化配置，`cron_list` 提供可观察状态，`cron_run_now`
允许测试而不等待时钟。执行路径计算
`nextRunAt`，到期后绑定工作区和运行选项，设置超时，保存回答或错误，并更新
`lastRunAt`。计划本身是持久副作用，必须走权限审批。

调度最容易被忽略的是并发与时间语义：应用休眠后错过的任务是否补跑？时区和夏令时如何解释？上一次未结束时是跳过、排队还是并发？多实例如何避免重复领取？生产实现通常需要租约锁、幂等执行
ID、失败退避和明确的 misfire 策略。

保存计划时不能固化明文 API Key；执行时应从凭据系统重新解析 Provider 配置。

## 运行与观察

```sh
deno task s14
```

创建一个短间隔测试任务，观察 `lastRunAt`、`nextRunAt` 和错误状态更新。

## 练习

为任务增加租约与唯一 execution
ID，模拟两个调度器同时扫描到期任务，确认只有一个成功领取。再分别定义“错过一次”和“上次仍在运行”的策略。
