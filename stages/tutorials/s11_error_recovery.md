# s11：错误恢复

源码：[s11_error_recovery.ts](../s11_error_recovery.ts)

## 学习目标

- 区分可重试与不可重试错误。
- 掌握指数退避、服务端 `retry-after` 和取消信号。
- 避免把工具业务错误当作网络错误重试。

## 核心机制

Provider 对超时、限流和服务端错误执行有限重试，并发出 `ErrorRecovery`
Hook。认证失败、参数错误等确定性问题立即返回。退避等待必须响应 `AbortSignal`。

## 先分类，后重试

重试不是“失败后再来一次”。限流、临时网络故障和 5xx
可能恢复；认证失败、非法参数和不存在的模型通常不会因等待而改变。盲目重试只会增加成本、延迟和重复副作用。

本课复用 s02 中的 `ProviderError` 与
`completionWithRecovery()`：根据状态和错误类别决定是否恢复，限制尝试次数，优先尊重服务端
`retry-after`，否则使用递增退避。每次等待都通过 `AbortSignal` 可取消，并借 `ErrorRecovery` Hook
暴露原因、次数和延迟。

Provider
请求通常是幂等读式操作；工具调用却可能已经写文件或发送消息。除非工具具有幂等键或可确认“尚未执行”，否则不应在
Provider 重试逻辑里自动重跑工具。恢复策略必须分层：传输层重试请求，Agent 层根据工具错误重新判断。

生产系统还应加入随机抖动避免请求同步重试、按 Provider 熔断、总重试预算以及错误指标。

## 运行与观察

```sh
deno task s11
```

使用错误地址或模拟限流，观察重试次数和等待时间，随后取消请求确认等待能够中止。

## 练习

加入随机抖动、总等待上限和按 Provider 统计的熔断状态。分别模拟 401、429、500
与取消，写出每种情况预期的尝试次数。
