# s06：Subagent 委派

源码：[s06_subagent.ts](../s06_subagent.ts)

## 学习目标

- 理解主 Agent 如何把聚焦任务委派给子 Agent。
- 理解为什么子 Agent 复用同一个 Agent Loop。
- 掌握递归委派限制和取消传播。

## 核心机制

`subagent` 将任务包装成更窄的提示，再调用同一个
`agentLoop()`。异步上下文标记当前已经处于委派中，阻止子 Agent 继续无限创建子 Agent。

## 子 Agent 的价值是上下文隔离

子 Agent
不会自动变得更聪明。它得到一份聚焦、干净的消息历史，只处理一个自包含问题，最后仅把结论带回主上下文；搜索过程和中间噪声因此不会挤占主
Agent 的注意力。

`subagent` Handler 再次调用 `todoAgentLoop()`，说明主从复用同一个 Loop 与能力栈。空历史 `[]`
建立隔离，任务前缀限定范围。`subagentActive` 在 `try/finally`
中恢复，防止失败后永久锁死，也禁止无界递归。

单布尔值适合教学，却也禁止安全的并行委派。生产实现应把深度放入运行上下文，并同时限制总子任务数、并发、工具、Token、时间和返回长度。任务委派必须携带目标、范围、证据、期望输出与完成标准；否则隔离会变成信息缺失。

短任务、共享大量动态状态或同一文件上的紧密修改通常不适合委派。

## 运行与观察

```sh
deno task s06
```

让主 Agent 委派一个只读代码分析任务，观察主任务与子任务的输入边界。

## 练习

把布尔值改为运行上下文中的 `depth`，允许深度 1、拒绝深度
2；增加工具白名单、超时与最大返回长度，并验证取消信号能抵达子 Agent。
